# AstrBot 日志分析器插件

一个功能强大的 AstrBot 插件，用于自动监控、抓取、分析和修复日志问题。

## ✨ 功能特性

### 🔍 自动监控
- 后台定时扫描日志文件（可配置扫描间隔）
- 匹配到关键词后自动发送给配置的管理员
- 智能去重机制，已发送的日志不会重复通知
- 支持日志文件轮转检测

### 📋 手动抓取（v1.4.0 增强）
- 按关键词搜索日志内容
- 支持时间范围过滤（`--since` / `--until`）
- **条目模式**：指定时间范围时，按「日志条目」匹配——关键词只匹配条目头部，但输出完整条目（含堆栈信息）
- **分页翻页**：支持 `--page N` 翻页，条目模式每页 5 条完整日志，行模式每页 20 行
- **结果缓存**：同一关键词 + 时间范围的查询缓存 5 分钟，翻页不重复扫描
- 支持不补零日期格式（如 `2026-6-21`）
- **性能优化**：有时间过滤时从文件尾部 512KB 读取，大日志文件秒级响应

### 🚨 告警优化（v1.2.0 新增）
- **告警阈值**：同一错误出现 N 次才告警，避免单次错误打扰
- **告警静默期**：某错误告警后，同类错误在 N 分钟内不再重复告警
- **关键词分级**：不同关键词设置不同告警级别（严重/错误/警告）

### 📊 错误统计（v1.2.0 新增）
- 统计各类错误出现的次数、频率
- 按日期、小时统计错误分布
- 查看 Top 10 高频错误
- 支持清空统计数据

### ⚙️ 热更新配置（v1.2.0 新增）
- 修改配置后无需重启插件
- 支持通过命令添加/删除监控关键词
- 配置修改立即生效

### 🤖 AI 分析
- 抓取日志后调用 AI 分析报错原因
- 自动生成问题诊断和解决建议
- 支持指定分析模型提供商

### 🔧 自动修复（v1.3.0 新增）
- 检测到错误后自动生成修复建议
- 提取可执行的 shell 命令
- 询问用户确认后执行
- 需要开启 AstrBot 电脑功能（Computer）
- 5 分钟超时保护

## 📦 安装

将插件文件夹放入 AstrBot 的 `data/plugins/` 目录下，重启 AstrBot 或在管理面板中启用插件。

## ⚙️ 配置

在 AstrBot 管理面板中配置以下选项：

### 基础配置

| 配置项 | 类型 | 说明 | 默认值 |
|:---|:---|:---|:---|
| `log_path` | string | 日志文件路径，留空使用默认路径 | `""` |
| `admins_id` | list | 管理员 ID 列表（权限控制 + 通知接收者） | `[]` |
| `monitor_enabled` | bool | 是否启用自动监控 | `false` |
| `monitor_interval` | int | 扫描间隔（秒） | `30` |
| `max_fetch_lines` | int | 单次抓取最大条目/行数 | `500` |

### 关键词配置

| 配置项 | 类型 | 说明 | 默认值 |
|:---|:---|:---|:---|
| `monitor_keywords` | list | 监控关键词列表，为空不启动监控 | `["ERROR", "Exception", "Traceback", "CRITICAL", "FATAL"]` |
| `critical_keywords` | list | 严重级别关键词 | `["CRITICAL", "FATAL", "PANIC"]` |
| `error_keywords` | list | 错误级别关键词 | `["ERROR", "Exception", "Traceback", "Failed"]` |
| `warning_keywords` | list | 警告级别关键词 | `["WARNING", "WARN"]` |

### 告警配置（v1.2.0 新增）

| 配置项 | 类型 | 说明 | 默认值 |
|:---|:---|:---|:---|
| `alert_threshold` | int | 同一关键词出现N次后才告警 | `1` |
| `alert_cooldown` | int | 告警静默期（秒） | `300` |

### 模型配置

| 配置项 | 类型 | 说明 | 默认值 |
|:---|:---|:---|:---|
| `analysis_provider_id` | string | 分析模型提供商ID，留空使用当前会话 | `""` |
| `analysis_model_name` | string | 分析模型名称，留空使用提供商默认模型 | `""` |
| `auto_analyze` | bool | 检测到错误后自动调用AI分析 | `false` |
| `auto_fix` | bool | 检测到错误后自动生成修复建议并询问是否执行 | `false` |

**注意**：`auto_fix` 功能需要开启 AstrBot 的电脑功能（Computer）才能自动执行修复命令。

### 配置示例

```json
{
  "log_path": "",
  "admins_id": ["12345678", "87654321"],
  "monitor_enabled": true,
  "monitor_keywords": ["ERROR", "Exception", "Traceback", "CRITICAL"],
  "critical_keywords": ["CRITICAL", "FATAL"],
  "error_keywords": ["ERROR", "Exception"],
  "warning_keywords": ["WARNING", "WARN"],
  "max_fetch_lines": 500,
  "alert_threshold": 3,
  "alert_cooldown": 600,
  "monitor_interval": 30,
  "analysis_provider_id": "",
  "analysis_model_name": ""
}
```

### 日志操作

| 命令 | 功能 | 示例 |
|:---|:---|:---|
| `日志抓取` | 手动抓取日志（支持分页） | `日志抓取 ERROR --since 2026-06-21 13:57 --page 2` |
| `日志分析` | 抓取 + AI 分析 | `日志分析 Exception` |
| `日志修复` | 抓取 + 分析 + 修复方案 | `日志修复 ERROR` |
| `日志执行修复` | 执行修复命令 | `日志执行修复 systemctl restart astrbot` |
| `日志路径` | 查看/设置日志路径 | `日志路径` |

**日志抓取命令格式**：
```
日志抓取 关键词 [--since 时间] [--until 时间] [--page N]
```

**参数说明**：
- `关键词`：要搜索的日志关键词（必填）
- `--since`：起始时间，可选。指定后进入「条目模式」，按完整日志条目匹配和显示
- `--until`：结束时间，可选。指定后进入「条目模式」
- `--page N`：翻到第 N 页。同一查询结果缓存 5 分钟，翻页不重新扫描

> 💡 **条目模式 vs 行模式**：指定 `--since` 或 `--until` 时进入条目模式——关键词只匹配日志条目的头部行，但输出整个条目（含后续堆栈信息），每页显示 5 个完整条目。不指定时间范围时进入行模式——逐行匹配，每页 20 行。

**示例**：
```bash
# 逐行搜索（行模式）
日志抓取 ERROR

# 条目模式：搜索 13:57 之后的完整错误条目
日志抓取 ERRO --since "2026-06-21 13:57"

# 条目模式 + 指定时间范围 + 翻页
日志抓取 ERRO --since "2026-06-21 13:57" --page 2

# 条目模式：搜索 19:00 到 19:30 之间的 websocket 错误
日志抓取 websocket --since 19:00 --until 19:30

# 不补零日期也支持
日志抓取 ERROR --since 2026-6-21 13:57
```

## 📖 使用示例

### 1. 启动自动监控

```
日志监控 启动
```

当日志中出现配置的关键词时，插件会自动发送通知给配置中的 `admins_id` 用户。

### 2. 条目模式抓取（带分页）

```bash
# 第一次查询
日志抓取 ERRO --since "2026-06-21 13:57"
# 显示第 1/29 页，每页 5 条完整条目

# 翻到第 2 页
日志抓取 ERRO --since "2026-06-21 13:57" --page 2
# 5 分钟内的翻页会使用缓存，不重新扫描
```

### 3. 查看错误统计

```
日志统计
```

显示 Top 10 高频错误及其出现次数。

### 4. 调整告警阈值

在配置文件中设置：
```json
{
  "alert_threshold": 5,
  "alert_cooldown": 600
}
```

然后执行热更新：
```
日志配置 热更新
```

### 5. 动态添加关键词

```
日志关键词 添加 ConnectionTimeout
```

无需重启，立即生效。

## 🔒 权限控制

- 只有 `admins_id` 列表中的用户才能使用所有命令
- 群主、群管理员默认无权限（除非在列表中）
- 自动监控通知只发送给 `admins_id` 中的用户

## ⚠️ 安全特性

### 危险命令拦截

以下危险命令会被自动拦截，拒绝执行：

- `rm -rf` - 递归删除
- `mkfs` - 格式化磁盘
- `dd if=` - 磁盘写入
- `chmod 777 /` - 危险权限修改
- `:(){ :|:& };:` - Fork 炸弹

### 执行确认

所有修复命令执行前都需要二次确认，防止误操作。
